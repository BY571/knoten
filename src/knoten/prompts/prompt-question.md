# knoten stage - question

You are writing the root of the graph. There is nothing before this: it is the one
statement the whole graph descends from, and `knoten init` scaffolds it. Make it a task
you can actually answer, not a topic.

Write it as the `question` node, in one sentence. Then record the bar a result of this
graph has to survive, so nothing can quietly violate it later.

Scaffold:

# <the question, one sentence>

## The bar
The result this graph must survive, stated as a relationship between measurable quantities
with a threshold, so a claim either passes or fails and it is not a judgement call. For
example "net of the costs this work has to pay, at a price actually reachable, on a forward
test it did not fail". State the bar for THIS graph, not one borrowed from elsewhere.

## What "answered" looks like
The concrete criterion the graph is trying to reach. A question with no exit condition
never closes; it just accumulates nodes around it.

Rules that matter here:

- A question with nothing behind it IS that why, so it needs no citation.
- Choose the question you can actually settle. "Is there an edge?" is not answerable; a
  question with a measure and a threshold is.
